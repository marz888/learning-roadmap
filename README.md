# Solutions Architect (Applied AI) Training Plan

A 26-week, 496-hour plan to prepare for a Solutions Architect role on a startups-focused applied AI team.
4 hours a day, Monday to Friday, 9 Nov 2026 – 7 May 2027, excluding England & Wales bank holidays.

**The plan lives in this repo's [Issues](../../issues) and [Milestones](../../milestones).**
Each week is one milestone (due on its last working day) and one issue with a checklist of subtasks.

## Phases

| Phase | Weeks | Hours | Label | Goal |
| --- | --- | --- | --- | --- |
| 1. Foundations | 1–4 | 80 | `phase: foundations` | Fluent with the Claude API and modern Python |
| 2. Core builds | 5–14 | 188 | `phase: core builds` | Build the three most common startup patterns: RAG, agents, document extraction |
| 3. Evals | 15–18 | 80 | `phase: evals` | Eval frameworks: the skill the role relies on most |
| 4. Customer-facing | 19–23 | 92 | `phase: customer-facing` | Real engagements with startups; a workshop |
| 5. Job readiness | 24–26 | 56 | `phase: job readiness` | Interview prep and applications |

Bank holidays excluded: 25 Dec, 28 Dec 2026; 1 Jan, 26 Mar, 29 Mar, 3 May 2027.

## How to use it

- **Tick off subtasks** in each week's issue as you finish them. GitHub shows progress (e.g. "3 of 5 tasks").
- **Close the issue** when the Friday deliverable is published. Each milestone page shows % complete.
- **Add a task:** New issue → "Task" template → pick the week's milestone and a phase label.
- **Move a task to another week:** change its milestone.
- **Remove a task:** close it as "not planned".
- **Change timings:** edit a milestone's due date, or the hours line in an issue.
- **Slipped week:** add the `slipped` label and move unfinished subtasks into the next week's issue.

## Board view (GitHub Projects)

1. Go to your profile → **Projects** → **New project** → choose **Board** (or **Table**).
2. In the project's **⋯ → Workflows**, turn on **Auto-add to project** with the filter `repo:marz888/learning-roadmap is:issue`,
   or use **+ Add item** and paste `repo:marz888/learning-roadmap` to add all issues at once.
3. Add a **Table** view grouped by **Milestone** for a week-by-week list, and a **Board** view by **Status** (Todo / In progress / Done).
4. Optional: add a number field **Hours** and date fields **Start** / **End** for the **Roadmap** view.

## Weekly review (every Friday, 15 minutes)

1. Did the Friday deliverable ship publicly? If not, what blocked it?
2. What could I now explain to a founder that I couldn't on Monday?
3. What broke, and what did fixing it teach me?
4. Who did I talk to this week, and what did I learn about how startups build?

If behind: one week → drop reading and stretch goals; two weeks → merge two light weeks (7+8 or 12+14).
Never cut weeks 15–23 (evals and engagements).
